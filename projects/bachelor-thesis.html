Buck converter control using Gaussian Process Regression

Bachelor thesis: I designed a buck converter, built a machine-learning controller for it in Python, and benchmarked it against a commercial analog buck converter IC.

The question

Buck converters step a higher voltage down to a lower one and are normally regulated by fast analog control circuits. A load change involving a capacitive (RC) load is still a hard case, because the charging capacitors cause a transient that slows regulation down.

My thesis asked whether a data-driven controller based on Gaussian Process Regression (GPR) can hold the output voltage during such a load change, and how it compares with a conventional buck converter IC (Texas Instruments TPS629210).

Hardware

  • Designed an asynchronous buck converter (100 kHz switching, AOI4286 MOSFET, 1N5817 Schottky diode). I prototyped it on perfboard, then designed a PCB in KiCad, which was fabricated at RF-Frontend.
  • Traced high-frequency noise on the output to voltage spikes in the PWM signal and removed it by adding a comparator stage.
  • Diagnosed a ground loop (5.48 V between the measurement and supply grounds) and solved it with an optocoupler.
  • Built a switchable test load: a 1 kΩ base load plus an RC load (470 Ω ∥ 2 × 1 mF) connected through a MOSFET, with a shunt resistor to measure the load current.

Software & machine learning

  • Wrote a Python module for the Analog Discovery 2 (WaveForms SDK) that generates the PWM signal, measures voltages and switches the test load.
  • Chose a buffer-averaged measurement (500 samples) over single samples: the noise dropped from 115 mV to 25 mV (standard deviation), at 0.76 ms instead of 0.18 ms latency.
  • Collected a dataset of 475 training and 475 test samples with random duty cycles across load resistances from 220 Ω to 1 kΩ.
  • Trained GPR models with scikit-learn, tuned hyperparameters with Bayesian optimization and compared four kernels. The Matérn kernel performed best (R² 0.991, MAE 2.18 percentage points of duty cycle).
  • Developed three controller versions: basic GPR, a variant that applies maximum duty cycle during the initial voltage drop, and a GPR + PI controller with anti-windup that removes the remaining steady-state error.

Results

  • Accuracy: both controllers held the load voltage within 1 % of the target. After the RC load was connected, the GPR+PI controller had a lower steady-state error than the IC (4–17 mV vs. 22–27 mV MAE).
  • Speed: the GPR controller settled in 108 ms against 36 ms for the IC. I traced the gap to the 2.19 ms control loop period (0.7 ms reading voltages, 0.7 ms computing, 0.8 ms updating the PWM signal), mostly USB and SDK overhead.
  • The analysis showed that a loop about 3× faster (≈0.73 ms) should match the IC, so the approach is competitive once these latencies are removed.

Next steps

The natural continuation is to run the controller on a microcontroller such as an STM32: train the GPR model offline, deploy it to the device, and measure and generate the PWM signal on-chip, removing the USB latency. Further ideas include giving the model a history of past measurements so it learns the transient behaviour, and using identical circuit topologies for a fairer comparison.
